# 方案设计：车道线识别与行人避障

> 修订：2026-10-29（v2，对齐四项目组合与测试岗定位）
> 定位：作品集第二项目。在四个项目的分工里承担两块：**几何视觉**（相机模型、标定、单目测距）和**单元测试体系**（分层、fixture、容差断言、回归基线）。深度学习训练流程由车牌项目承担，本项目不训练任何网络。
> 排期：对应总排期 A 阶段（4 个工作日）+ G 阶段的车道线测试部分（约 2 天）。

---

## 1. 目标与边界

### 要做的

一个单目视觉的驾驶辅助原型，三件事：

1. **车道线检测**：从单帧图像中定位本车道左右边界，输出曲线参数、曲率半径、车辆相对车道中心的横向偏移。
2. **行人检测**：识别画面中的行人，给出边界框与置信度。
3. **避障决策**：把行人位置换算成纵向距离，结合车速估计碰撞时间（TTC），输出分级告警。

输入支持图片与视频，输出带标注的视频与逐帧结构化数据（JSON）。

### 不做的（写进 README）

- **不做车辆控制**。只输出告警信号，不接转向/制动。
- **不做多传感器融合**。只有单目相机，没有雷达、IMU。
- **不训练任何网络**。车道线走传统视觉（理由见 2.2）；行人检测用 COCO 预训练权重。
- **不下载 TuSimple / CULane 全量数据**。官方指标（点级准确率、F1）只在报告里作为背景引用，说明传统方法与深度学习方法在这些基准上的公开差距，不在本项目上复现。

### 与其他项目的分工（简历上要讲清）

| | 森林火灾 | 本项目 | 车牌识别 |
|---|---|---|---|
| 场景 | 静态远景，固定机位 | 动态近景，相机随车运动 | 近景抓拍，角度倾斜 |
| 核心方法 | 深度学习检测 + 时序投票 | 几何计算 + 传统视觉 + 预训练检测 | 两个自训模型 + 后端 |

## 2. 技术路线

### 2.1 三个模块

```
视频帧
  ├─[A] 车道线分支
  │   二值化（颜色 + 梯度）
  │     → 透视变换到米制鸟瞰图
  │       → 滑窗搜索车道像素
  │         → 二次多项式拟合 x = f(z)
  │           → 曲率半径、中心偏移
  ├─[B] 行人分支
  │   YOLO 检测（COCO 预训练，只取 person 类）→ 框底中心点
  └─[C] 决策分支
      框底像素 → 同一套 homography → 纵向距离 Z
        → 距离平滑 → 相对速度 → TTC
          → 四级告警（安全 / 提示 / 警告 / 紧急）→ 叠加可视化
```

**核心设计：车道线和测距共用同一个 homography。**

透视变换把梯形 ROI 映射成米制鸟瞰图（横向约 8.2 米、纵向 6~40 米），于是：

- 车道线在鸟瞰图上近似变成抛物线，拟合有物理意义，曲率半径单位是米；
- 行人框底点经同一变换落到鸟瞰图上，`距离 = z_far − y_bird × 每像素米数`，不需要另外标定内参。

一套标定解决两个任务，是这个方案在工程上最值得展开讲的地方。

### 2.2 为什么车道线用传统视觉

| 方案 | 需要的数据 | 可解释性 | 训练成本 | 结论 |
|---|---|---|---|---|
| 训练 LaneNet / YOLO-seg | TuSimple 或 CULane 全量 | 低（黑盒） | GPU 数小时到数天 | 不选 |
| 传统视觉（本方案） | 不需要训练数据 | 高，每一步能画出来 | 零 | 选 |

三条理由：

1. **参数可解释**。ROI 由相机高度、俯仰角、视场角推出，不是手调四点。
2. **失败模式清晰**。能准确说清夜间、强逆光、车道线磨损时如何失效。
3. **与火灾、车牌项目不重复**。那两个项目已经覆盖深度学习训练，本项目展示几何建模。

代价如实写进报告：传统视觉在夜间、阴影、拥堵、无车道线场景上的表现会明显不如深度学习方法（CULane 公开榜上 CLRNet 约 77% F1，传统方法在挑战场景普遍低于 60%）。这是方法性质，不是实现缺陷。

### 2.3 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 鸟瞰图尺度 | x/y 尺度独立配置（约 0.02 / 0.048 m/px） | 按比例推导会让画面过窄；拟合在米制下做，不受像素比例影响 |
| 拟合阶数 | 二次 | 一次无法描述弯道；三次在 34 米范围内过拟合，远端抖动 |
| 拟合变量 | 纵向先归一化到 [-1,1] 再 polyfit | 6~40 米平方后到 1600，横向只有 ±4 米，直接拟合病态 |
| 左右线缺失 | 用车道宽 3.7 米外推，置信度乘 0.6 | 单侧检出时仍可用，但输出里要标注"外推" |
| 跨帧平滑 | 系数级 EMA，α=0.3 | 抑制拟合抖动；α 太大弯道响应滞后 |
| 行人检测后端 | 抽象接口，默认 YOLO，备选 HOG+SVM | HOG 不依赖 torch，用于无 GPU 环境与交叉验证 |

| 级别 | 数据集 | 体积 | 用途 | 状态 |

| 一 | Udacity CarND-LaneLines-P1：6 图 + 3 视频（含 challenge 1280×720，树影/明暗突变/弯道） | 26 MB | 开发调试、demo 录屏、v0 基线 | **已导入** `data/samples/` |

## 4. 评估方案

### 4.1 车道线检测

| 指标 | 真值来源 | 说明 |
|---|---|---|
| 车道宽反推误差 | 已知物理量 3.7 m | 最直观的正确性检查 |
| 曲率半径误差 | 合成数据（已知曲线参数） | 只有合成数据能给曲率真值 |
| 中心偏移误差 | 合成数据 | 车辆相对车道中心的横向偏差 |
| 投影往返误差 | 自身一致性 | 像素 → 鸟瞰 → 像素，应 < 1 px |

**合成数据的作用**：程序生成已知曲率、已知偏移的透视道路图，算出拟合误差的绝对值，而不是"看图觉得还行"。生成器同时是 pytest 的 fixture（见第 5 节）。

### 4.2 行人检测与测距

- 行人检测：在样例视频上人工核对 + KITTI（若下载）按遮挡等级分组报 Recall；与 HOG+SVM 后端对照，说明选型依据。
- 测距：KITTI 3D 标注为真值，按距离分桶（<10 / 10~20 / 20~30 / >30 m）报平均绝对误差与 P90。预期误差随距离增长（像素量化被几何放大），30 米外可能到 3~5 米，报告里提前承认。

### 4.3 对照实验

| 版本 | 方法 | 预期结论 |
|---|---|---|
| v0 基线 | HSV 阈值 → Canny → 比例 ROI → HoughLinesP → 一次拟合（复现原 notebook） | 直道可用，弯道偏出，无物理量输出 |
| v1 | 颜色+梯度 → 物理 ROI → 透视 → 滑窗 → 二次拟合 | 弯道改进、输出曲率与偏移 |
| v2 | v1 + 跨帧平滑 + 左右一致性校验 | 视频抖动下降，TTC 序列方差下降 |

v0 复现为 `scripts/baseline_hough.py`，同一批数据同口径对比。没有 v0，"改进"没有依据。

## 5. 测试体系（本项目的简历卖点之一）

测试体系的完整设计在总方案（`求职方案_测试岗_10天计划.md` 第 4 节），本项目的部分如下：

| 内容 | 做法 | 面试对应 |
|---|---|---|
| 分层 | `pytest -m unit`（纯函数、毫秒级）/ `integration`（读图，秒级）/ `slow`（视频） | CI 只跑前两层 |
| fixture 工厂 | `conftest.py` 提供合成道路图、标准配置、临时目录；不依赖任何下载数据 | "测试不依赖数据集，CI 秒级跑完" |
| 容差断言 | 透视往返 < 1 px、车道宽误差 < 0.5 m、拟合曲率误差上限，用 `pytest.approx` | 会写数值容差的人很少 |
| 参数化 | 曲率 × 偏移 × 分辨率组合跑同一断言 | pytest 核心考点 |
| 回归基线 | 固定输入的拟合参数存为 golden file，改动后对比；**基线不自动更新** | 图像算法改动最容易破坏别处 |
| 覆盖率 | core/ 与 lane/ 几何模块 ≥ 70%，低于门槛 CI 失败 | |

## 9. 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| 二值化调不到位（当前状态） | 滑窗被树丛带偏，物理量全错 | 先用合成数据验证几何链路正确，再回来调真实图；这样能区分是几何错还是阈值错 |
| 相机参数未知 | 距离整体偏移 | 参数集中 yaml；用 KITTI 数据反推等效焦距校验 |
| 平坦地面假设 | 坡道误差 | 报告量化坡度 5° 时误差增量 |
| challenge.mp4 失效 | demo 不好看 | 如实展示失败帧并归因，比隐藏更有说服力 |
| 8 小时/天连续投入的效率波动 | 进度拖后 | 按保底线砍，见第 8 节 |
