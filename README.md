# 车道线识别与行人避障（单目 ADAS 原型）

用一台普通单目相机做两件事：认出车道线并给出横向偏移、曲率半径；认出画面里的行人，估算距离，按碰撞时间（TTC）分四级告警。

不依赖深度学习做车道线——这套管线是传统视觉加几何投影，可以逐环节量出误差。行人检测用现成的 YOLOv8n 权重，不重新训练。

## 快速开始

```bash
python -m venv .venv
.venv/Scripts/activate            # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev,yolo]"      # 不跑行人检测时去掉 ,yolo（省 torch 的下载）

adas run data/samples/images/solidWhiteRight.jpg     # 单图
adas run data/samples/videos/solidYellowLeft.mp4     # 视频
adas eval  data/samples/videos/solidYellowLeft.mp4   # v0 基线对照
pytest -q                                            # 45 条测试，约 5 秒
```

不带参数的 `run` 会把标注媒体和逐帧 JSON 写到 `output/`，JSON 里既有每帧的车道、行人、告警，也有整段的汇总：检出率、偏移中位数、抖动、各阶段平均耗时。

视频文件不进仓库（`data/samples/videos/` 在 gitignore 里），图片样例随仓库。视频可用 Udacity CarND 的公开样例：`solidWhiteRight.mp4`、`solidYellowLeft.mp4`、`challenge.mp4`，行人的 `vtest.avi` 来自 OpenCV 官方样例。

## 结果

同一段 `solidYellowLeft.mp4` 前 300 帧，同口径对比：

| 版本 | 方法 | 检出率 | 偏移中位数 | 偏移抖动 | 单帧耗时 |
|---|---|---|---|---|---|
| v1 | 颜色+梯度 → 物理 ROI → 逆透视 → 滑窗 → 二次拟合 | 100% | 0.13 m | **0.007 m** | 154.8 ms |
| v0 | HSV 阈值 → Canny → 比例 ROI → HoughLinesP → 加权平均 | 100% | 0.207 m | 0.029 m | 3.0 ms |

抖动的定义是逐帧偏移的一阶差分绝对值的中位数，越低越稳。v1 把抖动压到 v0 的四分之一，代价是单帧慢 50 倍——这是 Python 逐窗口搜索的开销，换成 C++ 或向量化重写能大幅收窄，不是算法本身的复杂度。

单帧样例（`solidWhiteRight.jpg`，960×540）：车道检出、拟合置信度 0.913、车道宽 3.373 m（标称 3.7 m）。

## 三个模块

**车道线**（`lane/`）

颜色阈值（白 + 黄）与 Sobel 横向梯度取交，梯形 ROI 按物理尺寸而不是画面比例算，再逆透视到米制鸟瞰图（x 约 0.02 m/px、y 约 0.048 m/px）。拟合在鸟瞰图上做逐行质心的滑窗搜索，二次多项式，变量先归一化再 `polyfit`——6~40 米平方后到 1600，横向只有 ±4 米，直接拟合的病态程度无法接受。跨帧用系数级 EMA（α=0.3）抑制抖动。

**行人**（`obstacle/`）

检测器是抽象接口，默认 YOLOv8n（只取 COCO 的 person 类），备选 HOG+SVM——后者不依赖 torch，无 GPU 环境可跑，也用于交叉验证。测距用框底中点的脚点做逆投影：地平线以下、且落在有效纵深区间的点才采信。多目标用最近邻贪心关联（代价 = 横向像素差 + 2×距离差），距离做 EMA 平滑，连续 8 帧没匹配上的轨迹删除。

**决策**（`decision/`）

对每条轨迹用最近 1 秒窗口内的样本做最小二乘，斜率就是接近速度。TTC = 距离 / 接近速度，分四级：SAFE / HINT / WARNING / EMERGENCY，并保留一条只按距离触发的兜底判据，避免速度算不出来时反而不报警。

## 相机标定

车上没有标定板，但逆透视必须要焦距、离地高度、俯仰角。做法是把车道线本身当标定物：人工点出左右边界线，用"车道宽沿纵深恒定"作准则搜索俯仰角，得 **pitch = -3.8°**，焦距由镜头标称水平视场角 78° 推得约 593 px。

**绝对尺度有约 10% 的不确定度，不能用来宣称"绝对距离精度 X 米"。** 沿纵深测宽得到 6 米处 3.36 m、35 米处 3.89 m，相对漂移约 15%。原因是焦距与离地高度在这类图像上耦合（同比例放大产生完全相同的投影），加上远端车道线像素稀疏、拟合靠外推。

横向偏移、曲率半径、行人相对距离都在同一套投影下计算，系统性尺度误差会约掉，按相对量使用是成立的。详细推导和两处判据修正见 `docs/方案设计.md` 第 2.4 节。

## 测试

45 条，分两层：`unit` 是纯函数与合成数据，毫秒级；`integration` 读样例图或跑命令行，秒级。`pytest.ini` 用 marker 控制，默认跳过 `slow`（跑视频的那批）。

几条写测试时才想清楚的断言口径：

- 位置精度对所有工况都卡：`z = 8/15/25 m` 三处，拟合位置与解析真值之差 < 0.25 m。
- 曲率只在可辨识区间卡：`R < 350 m` 时相对误差 < 40%。`R = 500 m` 时二次项在 36 米跨度上的垂度不到 0.2 m，低于像素量化能分辨的量级，报出来的数字没有意义，不做断言。
- 黄金基线（`tests/golden/`）存固定输入的拟合参数，改动后对比。基线不自动更新，要用 `REGEN_GOLDEN=1` 显式重建。

覆盖率 72%：`pipeline` 98%、`visualize` 96%、`distance` 96%、`ttc` 94%、`road` 94%、`fit` 91%、`config` 90%。偏低的三处是 `pedestrian` 57%（YOLO 分支要权重，测试只覆盖 HOG 与工厂）、`calibrate` 34%（自动配对在样例图上经常配不上对，属已知局限）、`cli` 39%（视频、baseline、eval 三条路径需要仓库外的视频文件）。

## 结构

```
src/adas/
├── core/        相机模型、地面投影、配置（pydantic + yaml）
├── lane/        二值化、逆透视、滑窗拟合、标定
├── obstacle/    行人检测（YOLO / HOG 两后端）、脚点测距与跟踪
├── decision/    TTC 分级告警
├── synthetic/   合成道路图生成器（测试用，已知曲率与偏移的真值）
├── baseline.py  v0 Hough 基线
├── pipeline.py  分阶段计时与组装
├── visualize.py 叠加绘制
└── cli.py       run / baseline / eval
```

## 边界

- 不训练车道线网络。车道线是几何问题，传统视觉的每一步都能单独量误差，比一个说不清为什么错的黑盒更适合作为能力证明。
- 行人只用 COCO 的 person 类，不检测其他障碍物，也不做多类跟踪。
- 假设地面平坦。坡道上测距会有系统偏差，没做坡度补偿。
- 未做时间同步与多传感器融合，单目单帧加跨帧平滑。
- KITTI 真值没下，测距精度目前只有人工核对，没有分桶的量化误差表。
